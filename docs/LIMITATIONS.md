# Ограничения мониторинга без прав администратора

Документ описывает, что RDP Connection Monitor **может** и **не может** узнать на корпоративном
Windows 10/11 под обычной учётной записью, и как приложение ведёт себя в каждом случае.
Принцип: если источник недоступен, приложение продолжает работать с остальными и честно
показывает ограничение. Предположение никогда не выдаётся за подтверждённое подключение.

## 1. Источники данных

| Источник | Что даёт | Доступ обычному пользователю | Поведение при отказе |
|---|---|---|---|
| **WTS API** (`WTSEnumerateSessionsW`, `WTSQuerySessionInformationW`) | Все сеансы, состояние, пользователь, IP и имя клиента, протокол (консоль/RDP), время входа/подключения | Да — стандартные разрешения слушателя RDP-Tcp дают группе «Пользователи» право *Query Information*. Организация может это право отозвать | Резервный источник `query user` (без IP); если и он недоступен — статус «Недостаточно данных» |
| **GetSystemMetrics** `SM_REMOTESESSION` / `SM_REMOTECONTROL` | Является ли *ваш* сеанс удалённым; управляется ли он удалённо (теневое подключение) | Да, всегда | — |
| **WTSRegisterSessionNotification** | Мгновенное событие при подключении/отключении/блокировке сеанса → внеочередная проверка | Да | Работает обычный опрос |
| **Журнал TerminalServices-LocalSessionManager/Operational** | 21 вход, 22 оболочка, 23 выход, 24 отключение, 25 переподключение, 39 отключение другим сеансом — с IP | Обычно да (канал читаем для интерактивных пользователей), но может быть закрыт политикой | Источник помечается «Нет доступа», перепроверка раз в 10 минут |
| **Журнал TerminalServices-RemoteConnectionManager/Operational** | 1149 аутентификация (с IP), 261 входящее соединение, 20503–20513 теневые подключения | Обычно да | То же |
| **Журнал Security** | 4624/4634 (тип 10/12), 4647, 4778, 4779 | **Как правило, нет.** Нужны права администратора или группа *Event Log Readers* | «Windows не разрешает обычному пользователю просматривать Security Event Log. Мониторинг продолжится через доступные источники» |
| **Таблица TCP** (`GetExtendedTcpTable` через psutil) | Установленные соединения с локальным RDP-портом и **IP удалённой стороны** — даже до входа в сеанс | Да | Источник помечается «Ошибка» |
| **Реестр HKLM\…\Terminal Server** (только чтение) | Включён ли RDP, номер порта, политика теневых подключений | Да | Значения «не удалось прочитать» |
| **Список процессов** (psutil) | AnyDesk, TeamViewer, RustDesk, VNC, Chrome RD, Quick Assist, msra, компоненты RDP Shadow, SCCM Remote Control и др. | Да (имена процессов других пользователей видны, владелец — нет) | — |
| **Журналы программ** (`connection_trace.txt` AnyDesk, `Connections_incoming.txt` TeamViewer) | История входящих подключений этих программ | Если файлы читаемы | Пропускаются |

## 2. Уровни достоверности

| Уровень | Когда ставится |
|---|---|
| **Подтверждено** | RDP-сеанс наблюдается прямо сейчас через WTS API, либо вход подтверждён двумя независимыми источниками (например, LSM 21 + Security 4624) |
| **Высокая** | Одна надёжная запись о входе в RDP-сеанс (LSM 21/22/25, Security 4624 тип 10, 4778), теневое подключение по журналу или `SM_REMOTECONTROL`, 1149 с подтверждённым входом |
| **Средняя** | TCP-соединение с RDP-портом; процессы RDP Shadow; запись о входящем подключении в журнале AnyDesk/TeamViewer |
| **Низкая** | 1149 без подтверждения входа; 261 (принято соединение) |
| **Информация** | Запуск/остановка программ удалённого доступа, локальные входы/выходы |

**Event ID 1149 сам по себе не доказывает доступ к рабочему столу**: он означает лишь успешную
сетевую аутентификацию. Если в окне ±3 минуты есть вход в сеанс того же пользователя или с того же IP,
достоверность повышается до «Высокая», иначе остаётся «Низкая».

## 3. Три состояния главного индикатора

* 🔴 **Обнаружено активное RDP-подключение** — есть RDP-сеанс в состоянии Active/Connected по WTS API,
  либо ваш сеанс удалённый (`SM_REMOTESESSION`), либо им управляют удалённо (`SM_REMOTECONTROL`).
* 🟢 **Удалённых подключений не обнаружено** — WTS API доступен и RDP-сеансов нет.
  Это **не** гарантия отсутствия иного удалённого наблюдения (см. раздел 4).
* 🟡 **Недостаточно данных** — перечисление сеансов недоступно, **или** есть неподтверждённые признаки:
  процессы RDP Shadow, TCP-соединение с RDP-портом без RDP-сеанса.

Недоступность журнала Security **не** делает статус жёлтым — на корпоративных ПК это нормальное состояние,
и оно отражено на вкладке «Диагностика».

## 4. Что монитор не может обнаружить

* **Корпоративные средства удалённого управления**, работающие как службы (SCCM/ConfigMgr Remote Control,
  агенты RMM): процесс службы виден, но наличие активного сеанса определить нельзя. ConfigMgr по умолчанию
  показывает панель уведомления пользователю — это настраивается администратором.
* **Демонстрация экрана** в Teams, Zoom, Telegram, браузере и т.п. — это не удалённое подключение к Windows.
* **Аппаратные средства** (Intel AMT/vPro KVM, IP-KVM) — работают ниже уровня ОС.
* **Удалённые команды без интерфейса** (PowerShell Remoting/WinRM, PsExec, WMI, SSH) — не создают RDP-сеанс;
  их следы — в журнале Security и Microsoft-Windows-WinRM, обычно недоступных пользователю.
* **AnyDesk/TeamViewer/RustDesk и т.п.**: факт запуска процесса ≠ подключение. Монитор не читает память
  чужих процессов. Подтверждение возможно только по журналам самих программ (если они доступны).
* **Quick Assist / Удалённый помощник**: процесс есть у обеих сторон; наличие процесса не доказывает сеанс.

## 5. Особенности Windows 10/11 (клиентские редакции)

* Одновременно возможен только **один** интерактивный сеанс. Если администратор подключится по RDP под
  другой учётной записью, ваш сеанс будет **отключён** (Windows обычно спросит согласие на экране,
  если вы залогинены). Монитор продолжит работать в отключённом сеансе, запишет события в историю и при
  вашем возвращении покажет уведомление «Пока ваш сеанс был отключён».
* Если кто-то подключится по RDP **под вашей учётной записью**, ваш консольный сеанс переключится на
  удалённый — монитор зафиксирует это как «Существующий локальный сеанс подключён удалённо по RDP».
* При **теневом подключении** (RDP Shadow) новый сеанс не создаётся. Признаки: `SM_REMOTECONTROL`,
  процессы `RdpSaProxy.exe`/`RdpSaUacHelper.exe`/`RdpSa.exe`, события 20503–20513 в журнале RCM.
  Нумерация событий 2050x различается в источниках, поэтому в «Подробностях» показывается текст события,
  сформированный самой Windows.

## 6. Что приложение никогда не делает

Не запрашивает UAC (манифест `asInvoker`), не устанавливает службы и драйверы, не меняет политики, реестр,
настройки RDP и брандмауэра, не повышает привилегии, не внедряется в процессы и не читает их память,
не отправляет данные в сеть. Реестр открывается только с `KEY_READ`.

## 7. Что проверено и что нет

* Логика обнаружения, корреляции, дедупликации уведомлений, хранения и интерфейс покрыты автотестами,
  которые выполняются на любой ОС с подставными источниками данных.
* Вызовы Windows API (ctypes) написаны по документации Microsoft, но **в среде разработки не запускались
  на реальной Windows**. Перед использованием выполните `RDPConnectionMonitor.exe --probe` и проверьте
  вкладку «Диагностика» (см. README, раздел «Первая проверка на вашем ноутбуке»).
